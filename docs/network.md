# Сеть и шина сообщений

Реализованы транспорт, discovery и мост шины. Доказательства на ПК:
`network/tests/transport_test.lua`, `network/tests/discovery_test.lua`,
`bus/tests/network_bridge_test.lua`, `tests/network_system_test.lua`.
Фактическое взаимодействие игровых карт ещё не проверено.
RPC, сертификаты и удалённые модели описаны в [rpc.md](rpc.md).

## Транспорт

В OpenOS включить `network.enabled`. По умолчанию используются все компоненты
`modem` и `tunnel`; `network.cards` ограничивает их по полным component address.
Для беспроводной карты можно явно задать `strength`. Адрес компьютера и канал
Linked Card не подменяют адрес карты при маршрутизации.

Все модемы используют один физический порт, по умолчанию 27015. Linked Card
не имеет аппаратных портов, её raw-событие приходит с портом 0. Логический порт
приложения находится в общем заголовке. Отправка в обоих случаях физически
широковещательная, принимающая сторона проверяет адрес назначения.

```lua
local transport = app.network
-- На всех выбранных картах:
local report, err, failedReport = transport:broadcast(1234, "payload")
-- На одной конкретной карте:
transport:broadcast(1234, "payload", "local-card-address")
-- Адресное сообщение, в основе также broadcast:
transport:send("recipient-card-address", 1234, "payload")
-- Выбор списка исходящих карт и отдельного сервиса:
transport:send("recipient-card-address", 1234, "payload",
  {"local-card-one", "local-card-two"}, "my-service")
```

`report` содержит `{id, sent, cards={address={ok, fragments, error}}}`.
`sent` — число интерфейсов, полностью принявших отправку, а не подтверждение
получения удалённым хостом. Ошибка одной карты не прерывает другие. Если ни один
интерфейс не отправил сообщение полностью, результат `nil, "ENETUNREACH", report`.
Указанный адресат должен совпасть именно с принимающей картой; `*` означает всех.

После полной сборки сообщения генерируется сигнал:

```lua
"spacecross_network_message", receivingCard, sourceCard, destination,
logicalPort, service, payload, messageId
```

Raw `modem_message` содержит только одну строку `SCN1:` + data-only codec.
В заголовке есть версия, ID сообщения, источник/адресат, логический порт,
сервис, номер/количество фрагментов и строковый фрагмент. Никакой Lua-код
из сети не выполняется. Источник заголовка должен совпасть с источником raw-сигнала.
Собственные отправки на соседнюю карту того же компьютера подавляются.

Сообщение разбивается с учётом `maxPacketSize()` и двух байт overhead
строкового аргумента. Число фрагментов, размер сообщения, число незаконченных
сборок на хост/источник, общий объём памяти и срок сборки ограничены конфигом.
Фрагменты можно получать в любом порядке. Конфликт одинаковых номеров
с разным содержимым сбрасывает сборку. Истёкшие сборки очищаются таймером.
При нескольких входящих интерфейсах сборки и транспортная дедупликация
разделены по принимающей карте, чтобы не смешивать её правила доступа.
На каждой карте сообщение выдаётся один раз в пределах `seenTTL`.

UUID сессии и счётчик предотвращают обычные коллизии сообщений; это не
криптографическая защита от атакующего или повторной передачи после TTL.
Гарантии доставки/ACK и доверие должны обеспечиваться протоколом клиента.
Для RPC реализована отдельная проверка сертификата и защита от replay.

Горячее добавление/удаление карт отслеживается через OpenOS events.
При завершении транспорт закрывает только самостоятельно открытые порты.
Заданная сила сигнала восстанавливается, если другой процесс не изменил её
после настройки транспорта. Уже открытый чужой порт не закрывается.

## Discovery

`app.discovery:list()` возвращает свежий список доступных интерфейсов хостов;
`list("power")` фильтрует по типу. Формат элемента:

```lua
{
  host_name = "Power controller",
  address = "remote-card-address",
  type = {"reactors_controller", "capacitors_controller"}, -- либо nil
  description = "optional description",                    -- либо nil
  last_seen = 123.4,
  reachable_via = {"local-card-address"},
  verified = false,
}
```

Имя/типы/описание являются объявленными самим хостом метаданными.
`verified=false` намеренно не меняется от того, что адрес доступен или совпадает
с именем owner. Discovery не выдаёт права доступа и не заменяет сертификат.
Каждая карта рекламирует собственный адрес. Несколько карт одного компьютера
представлены отдельными маршрутами; объединение доверенных моделей относится к RPC/UI.

Протокол сервиса `discovery` использует логический порт 27014: `query`, `announce`,
`bye`. На старте и при подключении новой карты отправляется запрос и объявление.
Объявления повторяются раз в `interval` (по умолчанию 10 секунд), пропавшие
маршруты истекают через `ttl` (35 секунд). Ответы на query ограничены по частоте;
таблица хостов имеет верхнюю границу. При нормальном stop отправляется bye.
Изменения доступны как `spacecross_host_changed`/`spacecross_host_lost` с адресом.

`discovery:setProfile({host_name=..., type={...}, description=...})` обновляет
собственное объявление. Без явного `type` приложение рекламирует имена своих
доступных моделей. Модель `network` показывает интерфейсы, discovery и статистику;
вкладка Network показывает адреса найденных карт. Выбор remote-компонентов
и их управляющие представления подключены через аутентифицированный RPC.

## Сетевой мост локальной шины

Включается отдельно: `network.bus.enabled`. Порядок запуска:
локальная шина → транспорт → discovery → мост. При остановке — обратный.
Приложение уже соблюдает этот порядок.

Правила задаются отдельно для `inbound` и `outbound`, глобально и в `cards[address]`:

```lua
bus = {
  enabled = true,
  outbound = {
    forwardLocal = true,
    whitelist = {ports = {27103}, msg_types = {"event"}},
    blacklist = {peers = {"blocked-card-address"}},
  },
  inbound = {whitelist = {ports = {27103}, msg_types = {"event"}}},
  cards = {
    ["private-card-address"] = false,
    ["public-card-address"] = {outbound = {blacklist = {ports = {27102}}}},
  },
}
```

Категории whitelist/blacklist: `ports`, `msg_types`, `peers`. Все заданные поля
whitelist должны совпасть, любое совпадение blacklist запрещает пересылку.
Правило карты дополнительно сужает глобальное. При отсутствии whitelist/blacklist
правило пропускает сообщения; `cards[address]=false` запрещает эту карту именно
для моста, но не отключает её discovery/прочие сервисы транспорта.

`dst_addr=nil` остаётся локальным, пока явно не включён `forwardLocal` для его
пересылки; при пересылке адресат становится `*`. `*` и конкретный адрес имеют
сетевое назначение и всё равно проходят через фильтры. Порт, тип и строковый
payload конверта сохраняются. Wire-копия не принимает произвольный `src_addr`;
входящая шина получает проверенный транспортом адрес отправившей карты.

Входящий конверт также должен совпасть с портом и адресатом транспортного
заголовка. Мост дедуплицирует сообщение после проверки правил каждой входящей
карты. Запрещённая копия не подавляет разрешённую. Полученные сетевые сообщения
не пересылаются повторно: кольцо эхо между компьютерами не образуется.

Обычные события шины остаются неаутентифицированными данными. В частности,
по ним нельзя объявлять подтверждённый owner/доверенный heartbeat или вызывать
физическую модель от имени игрока. Такие операции относятся к RPC-шлюзу.
