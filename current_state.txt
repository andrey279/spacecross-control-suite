Эта итерация — ПРОГРЕСС: добавлен read-only OpenOS component inspector для
сбора установленных component types, method names/direct-call flags и docs.
Инспектор запускается из `bin/inspect_components.lua` с корректным project
`package.path`; он не вызывает hardware methods. Его тесты покрывают фильтры, сортировку
и отказ перечисления. Основание API — официальная документация OC.
По upstream-исходнику Computronics подтверждены component type `radar`,
`getPlayers(distance)` и поля `name`, optional `x/y/z`, `distance`; adapter теперь
использует эти defaults и сохраняет explicit overrides для forks. Версия
установленного modpack всё ещё требует проверки через inspector в игре.
Тестами проверено смешивание OpenSecurity и настроенного Radar. В той же
итерации обязательное подтверждение waypoint стало fail-closed, а отмена/таймаут
навигации завершают deployment и отменяют переход. Добавлен
configured component-proxy adapter для builder/provisioning компьютера структуры,
включая receipt-based адрес. Предыдущая итерация добавила 10-секундный
heartbeat через authenticated CnC RPC, node-scoped whitelist/alerts в SQLite,
AES+HMAC local cache, component-proxy radar/WarpDrive/charge adapter, mine

Этап 4 — частично реализован, проверен на ПК; ожидает игры:
- network/transport.lua, protocol.lua, adapters/modem.lua, adapters/tunnel.lua:
  component-address routing, broadcast all/one/cards-list, addressed header,
  logical ports over one modem physical port and tunnel port 0, hotplug.
- Large string payload fragmentation, out-of-order assembly, per-card caches,
  limits per-message/per-peer/global-memory, TTL, malformed/header source checks,
  conflicting-fragment discard, independent hardware error handling.
- network/discovery.lua: query/announce/bye, per-card host records, types/description,
  receiving paths, expiry, bounded host cache and query response rate limiting.
  Discovery always verified=false, does not grant identity/access/heartbeat trust.
- bus/policy.lua and network_bridge.lua: inbound/outbound whitelist/blacklist
  ports/msg_types/peers, per-card restriction/disable, explicit forwardLocal,
  no reflection loops, accepted-interface dedup after policy (incl fragments).
- app network lifecycle and read-only model, ui/network_tab.lua, configuration.
  Default advertised type names come from installed models; networking is opt-in.
- PC integration: independent application instances discover and exchange live
  energy-controller events; stop/restart recovers; a broken network card leaves
  local services running. Network ports opened by another program remain open.
- Plain bus/discovery payloads remain unauthenticated data. Physical models are
  not exposed through unauthenticated bus commands. Transport dedup is not replay security.
- security/signing_card.lua: explicit OC Tier3 random/SHA256/ECDSA provider.
  security/certificates.lua: pinned CA, subject nick, addresses, client/server usage,
  model/action grants, revocation checked also after hello. No anonymous fallback.
- rpc/protocol.lua + service.lua: one logical RPC port, signed hello/challenge/
  invoke/result, request/recipient/port binding, fresh secure nonces, consume before
  dispatch, response retry cache, bounded sessions/serialized memory and expiration.
  Actor is cert.subject; args.player cannot impersonate another user. Model ACL
  owners/admins is checked in addition to certificate grants.
- Cache eviction/restart/replays do not repeat the old action. Signing failure
  after dispatch does not leave a request executable again. Timeout/result failure
  may mean unknown action outcome; the client does not silently create a new call.
- tools/pki.py, sc_codec.py: offline keygen/issue/inspect, exclusive file creation,
  0600 private DER keys. No CA deployment keys were installed or published.
  Static application certificates, no calendar expiration; explicit serial revocation.
- ui/remote_views.lua: authenticated _system.models catalog, selected endpoints,
  multi-host status/power/entity views; separate target command tabs. Certificate
  key+subject aliases deduplicated, inactive business snapshots never cached.
  framework guards reentrant refresh and discards responses for a changed tab.
- Network tab selects discovered model candidates; actual trust is provided by RPC,
  not discovery. App/runtime integrate separate server/client identity providers.
- RPC accepted actions and aggregated denial/fault statistics are passed to logger.
  API/format/PKI/limits: docs/rpc.md. RPC payload itself is signed, not encrypted.
- terminal/gpu.lua + text/cell/frame: software framebuffer без VRAM API, basic GPU
  get/set/fill/copy, colors/palette/resolution/viewport/depth; UTF-8 и wide cells,
  overlap/clipping/resize repair, строгий RLE SCT1 decoder. Квантизация low-depth
  цветов не эмулируется побитно; в OpenOS ширину задаёт native unicode.wlen.
- terminal/service.lua: owner-only (включая дополнительную проверку после model ACL),
  server-generated actor/sources, session ownership, atomic input validation,
  sequence ACK/dedup/conflict, queue/cells/session/frame/TTL limits, resize/close.
  MaxCells резервируется по максимальному размеру каждой сессии, не стартовому.
  Busy guard защищает от reentry при yield Data Card entropy/старта программы;
  shutdown во время старта закрывает поздно полученный handle.
- frame фиксирует один снимок, chunk передаёт до 4096 bytes с token; текущий вывод
  не меняет pinned snapshot. Клиент получает целый кадр и валидирует до GPU calls;
  обрыв и повреждение не дают частичный redraw. Полный redraw без delta cache.
- terminal/openos_runner.lua + openos_scope.lua: штатные PTY/window/process/thread,
  private input queue + data.pull, virtual component GPU/screen/keyboard proxy,
  per-process pressed keys, копии vars/aliases. В root event queue только wake;
  remote raw input и Ctrl+C/interrupted туда не публикуются. Root window restored,
  headless setup через временный pure software bind. OpenOS/EEPROM files не меняются.
  Используются internal OpenOS APIs: конкретная сборка ещё требует игры.
  Modules с заранее cached physical GPU требуют адаптации к term.gpu/переданному
  component proxy. Owner shell не является sandbox; имеет полный доступ к ОС.
- terminal/client/input/renderer + bin/remote.lua + config.client.example.lua:
  стандартный OpenOS client, actor/keyboard/screen association, pending input retry,
  Ctrl+Alt+Q закрывает shell, restore исходных клеток/resolution/colors/depth/viewport.
  Client запускает только transport/RPC, не корабельные службы. RPC подписывает,
  но не шифрует экран/ввод. CLI закрывает сессию при неизвестном исходе input.
- App/runtime terminal lifecycle; stop terminal закрывает shell, остальные
  службы не затрагиваются. Документированные лимиты/протокол: docs/terminal.md.
- cnc/channel.lua: outgoing Internet Card TCP, nonblocking finishConnect/read/write,
  u32 length frames, partial I/O, pin certificate, budgets/backpressure/timeout,
  EOF/reconnect/backoff. Один RPC instance/port 27016 для LAN и CnC, интернет-карта
  сохраняет свой component address; peer — pinned external certificate address.
  Discovery/bus через Internet не пересылаются; анонимного command API нет.
- cnc/agent.lua: async begin/poll/take heartbeat и encrypted log upload, без network
  wait внутри logger. Одноразовый частный proof обновляет defense heartbeat;
  alive/discovery/повтор старого RPC result не могут обновить его. TCP connected
  и подтверждённый trusted различаются. Отключение CnC не останавливает local services.
- Server: server/crypto.py/rpc.py/main.py/store.py/control.py, config.example.json.
  Взаимные certificate pins + CA/usage/address/grants/revocation, тот же signed
  four-frame RPC. CnC identity обычно Owner с client+server usage; ship identity
  имеет только _cnc.heartbeat/_logs.put. Команды проходят также целевой model ACL.
  PC регистрирует подключение только после fresh heartbeat invoke.
- Python decrypt совместим с Lua ECDH/HKDF/AES128CBC/HMAC envelope. SQLite WAL/FULL
  transaction сохраняет sealed+plaintext+notification intent до signed receipt.
  Agent требует exact ID и ciphertext digest, только затем logger удаляет файл.
  Duplicate одинакового node/id/data даёт ACK, конфликт не перезаписывает запись.
  Node namespaces разделены. Server DB 0600; plaintext/private log key только на ПК.
- Durable Discord outbox: warning/error/critical, JSON bounded content/no mentions,
  wait=true, no redirects, 429 retry_after/backoff и восстановление attempts.
  Receipt не ждёт Discord. Внешний HTTP sender проверен mock, реальных сообщений нет.
- server.control CLI enqueue/get: команды хранятся в SQLite, статусы queued/running/
  done/failed/unknown; disconnect/timeout/restart после старта -> unknown без нового
  автоматического действия. Локальный доступ к БД даёт права configured PC identity.
- Logger сохраняет pending upload filename первым при изменении сортировки spool
  (10 перед 2 не может заблокировать receipt). Timer workload bounded 8 records/
  4 ACK files; явный flush/stop пытается обработать всю очередь.
- RPC lifecycle усилен: stop во время crypto yield не создаёт поздний call/challenge/
  dispatch; после crypto повторно проверяются quota/running и nonce collision.
- Runtime/app/config/README/CI/documentation связаны. Полный протокол/настройка:
  docs/cnc.md. RPC payload подписан, не зашифрован; log payload уже sealed отдельно.
